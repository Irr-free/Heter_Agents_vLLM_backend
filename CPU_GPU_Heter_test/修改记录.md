# vLLM CPU-GPU 异构 Decode Attention 修改记录

> 本记录覆盖截至 2026-05-12 的所有修改。

---

## 一、修改概述

本次修改将 **vLLM CPU 版本** 的内存管理（CPU Paged KV Cache）与 Decode 阶段 Self-Attention 算子，和 **vLLM GPU 版本** 的其他高性能算子（LayerNorm、MLP、Projection 等）进行拼接，实现 CPU-GPU 异构处理系统。

**核心设计**：
- **Prefill 阶段**：完全在 GPU 上执行（包括 Attention），利用 GPU 高并行能力处理长序列。
- **Prefill → Decode 过渡**：按 **layer-wise** 细粒度搬运，每层 Prefill 结束后立即将该层 GPU KV Cache 异步搬运到 CPU 主存。
- **Decode 阶段**：
  - 非 Attention 算子（LayerNorm、Linear、MLP）在 GPU 执行。
  - Self-Attention 在 CPU 执行，使用 Python Fallback 实现的 Paged Attention（原生 C++ CPU kernel `ops._C.cpu_attention_with_kv_cache` 在 GPU 编译目标下不可用）。
  - KV Cache 主存储位于 CPU Pinned Memory。

## 三、详细修改内容

### 文件 1：`vllm/v1/worker/utils.py`

#### 修改位置
函数 `bind_kv_cache()`（约第 512 行）

#### 修改内容
在原有绑定 GPU KV Cache 的逻辑之后，增加对所有 Attention 层的 CPU KV Cache 初始化触发：

```python
# 异构系统：为每个 Attention 层初始化 CPU KV Cache（主存）
for layer_name in kv_caches:
    if hasattr(forward_context[layer_name], 'init_cpu_kv_cache'):
        forward_context[layer_name].init_cpu_kv_cache()
```

#### 修改目的
确保模型加载完成后，每个 Attention 层都分配了 CPU Pinned Memory 的 KV Cache，供 Decode 阶段使用。

---

### 文件 2：`vllm/model_executor/layers/attention/attention.py`（核心重构）

#### 整体架构变化

原始方案（已废弃）：在 `forward()` 内部直接做 Prefill/Decode 分支，调用 `_cpu_decode_forward()`（带 `@torch.compiler.disable()`）。**该方案导致 torch.compile AOT 编译失败**（`Skip inlining` + `InductorError`）。

**最终方案**：将 CPU decode 路径完全移入已存在的 custom op `unified_attention_with_output` 内部执行。torch.compile 不会编译 custom op 内部逻辑，因此可以安全地进行跨设备操作（GPU→CPU→GPU）。

#### 具体修改点

**① `__init__` 末尾：增加 CPU KV Cache 相关成员**

```python
self.cpu_kv_cache: torch.Tensor | None = None
self._d2h_stream: torch.cuda.Stream | None = None
self.scale = scale
self.logits_soft_cap = logits_soft_cap
self.sinks = extra_impl_args.get("sinks")
```

**② 新增 `init_cpu_kv_cache()`**

由 `bind_kv_cache()` 调用。功能：
- 读取已绑定的 GPU KV Cache 形状
- 按 CPU PagedAttention layout 分配 pinned memory：`[2, num_blocks, num_kv_heads, block_size, head_size]`
- 初始化独立 CUDA Stream：`self._d2h_stream`

**关键修复（2026-05-12）**：vLLM 初始化流程中 `bind_kv_cache()` 会被调用两次（第一次绑定 profile dummy cache，第二次绑定真正的 KV cache）。原代码的 `if self.cpu_kv_cache is not None: return` guard 导致 CPU cache 始终保持 profile 期间的小尺寸（如 8 个 block），后续真实推理时 `slot_mapping` 越界。

修复后逻辑：
```python
if self.cpu_kv_cache is not None:
    if (self.cpu_kv_cache.shape[1] == num_blocks and
            self.cpu_kv_cache.shape[3] == block_size):
        return
    # shape 不匹配（profile run 后换成了真正的 KV cache），释放旧的
    self.cpu_kv_cache = None
    self._d2h_stream = None
```

**③ 新增 `_prefill_kv_to_cpu_async()`**

Prefill 阶段 layer-wise 细粒度搬运。功能：
- 在 `self._d2h_stream` 上执行 `non_blocking=True` 异步拷贝
- GPU layout → CPU layout 转换：`permute(0, 2, 1, 3)`

**④ 新增 `_decode_kv_to_cpu()`**

Decode 阶段将新生成的 K/V 写入 CPU Cache。功能：
- 将 `key`、`value`、`slot_mapping` 同步搬到 CPU
- 优先调用 `ops._C.cpu_attn_reshape_and_cache()`（GPU 编译目标下不可用）
- Fallback：调用 Python 实现的 `_cpu_attn_reshape_and_cache_fallback()`

**⑤ 新增 `_build_cpu_metadata()`**

构造 CPU Attention 所需的 metadata。将 GPU `attn_metadata` 中的关键 tensor 搬到 CPU：`query_start_loc`、`seq_lens`、`block_table`、`alibi_slopes` 等。

**⑥ 新增 `_cpu_paged_attention()`**

调用 CPU Paged Attention。优先调用 `ops._C.cpu_attention_with_kv_cache()`（GPU 编译目标下不可用）；Fallback 调用 `_cpu_paged_attention_fallback()`。

**⑦ 注册 `_cpu_paged_attention_fallback` 为 custom op**

```python
direct_register_custom_op(
    "cpu_paged_attention_fallback",
    _cpu_paged_attention_fallback,
    mutates_args=["output"],
    fake_impl=_cpu_paged_attention_fallback_fake,
    dispatch_key="CPU",  # 必须注册到 CPU，因为输入全是 CPU tensor
)
```

**⑧ 修改 `unified_attention_with_output`：内嵌 CPU decode 路径**

在 custom op 内部（torch.compile 不可见区域）增加条件判断：

```python
num_prefill_tokens = getattr(attn_metadata, 'num_prefill_tokens', 0)
if (
    (num_prefill_tokens == 0)
    and (query.numel() > 0)
    and (not is_cudagraph_capturing())  # 避免 dummy run / warmup 期间走 CPU 路径
    and (self.cpu_kv_cache is not None)
):
    # 1. 等待 async D2H
    # 2. K/V 写入 CPU Cache
    # 3. Q 搬到 CPU，执行 CPU Attention
    # 4. Output 搬回 GPU
    return

# 原有 GPU 路径
self.impl.forward(...)
```

**⑨ 简化 `forward()`**

移除原有的 Prefill/Decode 分支逻辑，恢复为统一调用 `unified_attention_with_output`。仅保留 `num_prefill_tokens > 0` 时的 async D2H 触发：

```python
if num_prefill_tokens > 0:
    self._prefill_kv_to_cpu_async()
# 统一调用 custom op
unified_attention_with_output(query, key, value, output, self.layer_name, ...)
```

**⑩ `_cpu_paged_attention_fallback` 数值修复**

- `torch.matmul(q_seq, k_seq.transpose(1, 2))` → `torch.einsum('qhd,hkd->qhk', q_seq, k_seq)`（修复 GQA batch 维度不匹配）
- 当 `q_seq.shape[0] == 1`（典型 decode）时跳过 causal mask（原逻辑误将 batch 偏移当作序列位置，导致错误 masking）

## 四、关键设计决策

### 1. Custom Op 作为 CPU 路径的"避风港"

`unified_attention_with_output` 本身就是 custom op（torch.compile 不可见）。将 CPU 路径内嵌其中，既避免了 graph break，又无需新增 op 接口。

### 2. `is_cudagraph_capturing()` 而非 `torch.cuda.is_current_stream_capturing()`

后者只在 CUDA stream 真正 capture 时返回 True，而 vLLM 的 profile/warmup 阶段全局标记已启用但 stream 尚未 capture。使用前者可避免 dummy run 误入 CPU 路径。

### 3. `dispatch_key="CPU"`

Python fallback 操作的全是 CPU tensor，必须注册到 CPU dispatch key，否则 PyTorch 会根据输入设备查找对应 backend 实现并报 `NotImplementedError`。

### 4. Layer-wise 细粒度搬运

每层 Prefill 结束后立即触发 async D2H，利用独立 CUDA Stream 与后续 layer 计算 overlap。

### 5. 双 KV Cache 架构

- **GPU KV Cache**：保留原有 GPU layout `[2, B, block_size, nkv, h]`，仅用于 Prefill 阶段临时存储。
- **CPU KV Cache**：采用 CPU PagedAttention layout `[2, B, nkv, block_size, h]`，作为 Decode 阶段主存。
- **转换方式**：Prefill 搬运时通过 `permute(0, 2, 1, 3)` 完成 layout 转换。

## 六、已知限制与后续优化

| 限制 | 说明 | 优化方向 |
|------|------|---------|
| **性能极低** | Python fallback 的 decode 吞吐仅 ~0.5 tokens/s（32 层 × CPU einsum） | 编译/注册真正的 C++ CPU kernel（`cpu_attention_with_kv_cache` / `cpu_attn_reshape_and_cache`） |
| **CUDA Graph 不兼容** | Pure decode 完全绕过 CUDA graph，损失了 graph 启动加速 | 将 CPU 路径包装为可被 Graph 捕获的 custom op，或在 Graph 外执行 |
| **Mixed Batch 未拆分** | Prefill+Decode 混合 batch 统一走 GPU 路径 | Phase 2 可按 `num_prefill_tokens` 切分，Prefill 走 GPU、Decode 走 CPU |
| **CPU KV Cache 内存占用大** | 与 GPU cache 1:1 分配 pinned memory | 按需分配、压缩（int8/fp8）或分层卸载 |
| `isa` 硬编码 | `_cpu_attn_reshape_and_cache_fallback` 未利用 SIMD | 使用 PyTorch 的 `torch.matmul` 优化或编译 C++ kernel |
