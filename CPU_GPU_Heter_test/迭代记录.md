# codex update 2026-05-12 17:04:39 UTC

## 本轮目标

修复上一轮 review 和端到端日志发现的关键问题：V1 FlashAttentionMetadata 没有 `num_prefill_tokens` 字段，导致当前代码把 44-token Prefill 误判为 pure decode，并在 Prefill 阶段进入 CPU Attention fallback。

## 修改内容

### 1. 修复 Prefill / Decode 路由判定

修改文件：

- `vllm/model_executor/layers/attention/attention.py`

新增 helper：

- `_heter_query_lens(attn_metadata)`
- `_heter_is_pure_decode(attn_metadata)`
- `_heter_should_sync_full_kv_to_cpu(attn_metadata)`

新的 pure decode 判定不再依赖 `num_prefill_tokens`，而是优先使用 V1 metadata 中真实存在的字段：

- `query_start_loc`
- `seq_lens`
- `max_query_len`

判定规则：

- 只有 `max_query_len == 1`
- 且每个 active request 的 `query_len == 1`
- 且 `seq_len > query_len`

才认为是已有上下文上的 single-token decode。这样可以区分：

- `query_len=44, seq_len=44`：真实 Prefill，不能走 CPU decode。
- `query_len=1, seq_len=1`：单 token Prefill，不能走 CPU decode。
- `query_len=1, seq_len>1`：真实 Decode，可以走 CPU decode。

### 2. 修复 Prefill KV Cache D2H 时序

原代码在 `forward()` 中、`unified_kv_cache_update()` 之前触发 `_prefill_kv_to_cpu_async()`，存在搬运旧 KV / 未更新 KV 的风险。

本轮修改为：

- `forward()` 不再直接触发 Prefill D2H。
- 在 `unified_attention_with_output()` 的 GPU attention 路径执行完成之后，再根据 metadata 判断是否需要 `_prefill_kv_to_cpu_async()`。
- CUDA graph capture 期间先判断 `is_cudagraph_capturing()`，直接绕开 CPU 路由和 D2H 判定，避免 capture 中读取 GPU metadata 触发 CPU sync。

本轮中间曾遇到一次启动失败：

- 原因：在 CUDA graph capture 期间调用 `_heter_is_pure_decode()`，其中 `.item()` 触发 GPU->CPU sync，报 `CUDA error: operation not permitted when stream is capturing`。
- 修复：将 `not is_cudagraph_capturing()` 放到路由判断的最前面，并在 post-GPU D2H 判定前同样先短路。

### 3. 新增测试

新增文件：

- `CPU_GPU_Heter_test/test_heter_decode_routing.py`

覆盖内容：

- FlashAttentionMetadata 风格、没有 `num_prefill_tokens` 时，44-token Prefill 不会被判定为 pure decode。
- 单 token Prefill 不会被判定为 pure decode。
- 单 token Decode 会被判定为 pure decode。
- Mixed Prefill/Decode 不会被整体判定为 pure decode。
- Prefill 的全量 KV D2H 发生在 GPU attention 路径之后。

更新文件：

- `CPU_GPU_Heter_test/test_module_level.py`

将路径选择测试从旧的 `num_prefill_tokens/num_decode_tokens` mock，改为更贴近 V1 FlashAttentionMetadata 的 `query_start_loc/seq_lens/max_query_len` mock。

## 对低内存带宽现象的当前解释

最可能原因不是 DRAM 带宽被打满，而是 CPU attention 的实际可并行度太低，且单 token decode 的工作粒度太碎。

结合现象：

- 机器空闲背景程序约 `10 GB/s` system memory throughput。
- 跑异构测试时约 `30 GB/s`，即本测试额外只贡献约 `20 GB/s`。
- direct kernel 元数据显示 `effective_thread_num=1`。
- 20/40 no-SMT 在大多数 6K/8K case 中显著快于 OMP120。

因此更符合的解释是：当前 decode CPU attention 的瓶颈主要是小粒度单 token kernel、OpenMP parallel region/worker 调度、CPU 核抢占、cache/NUMA 干扰，以及 QK/PV tile 微内核的延迟暴露不足；它没有形成足够多独立、连续、长时间运行的内存流去压满整机 DDR 带宽。`htop` 看到很多核忙，不等于这些核在持续发起高带宽 DRAM stream；它们可能在执行别的用户程序、调度、同步、自旋或被抢占，也可能只是在消耗计算/前端/缓存资源。

## 下一步建议

1. 当前异构路径应优先降低 OpenMP 线程数，避免默认 120/128 worker 参与单 token decode attention。
2. 如果要让 CPU attention 真正利用多核，需要重新打开或修正 `enable_kv_split=True` 的调度路径，并验证 reduction/sync 成本是否小于多线程 KV split 收益。
3. 端到端慢的问题还需要继续看每层每 token 的 CPU/GPU 同步和 OpenMP team 创建/唤醒成本；direct kernel 只证明 kernel 本体在合适线程数下并不需要 120 线程。

### 1. 修复 torch.compile AOT 编译失败（架构重构）

#### 问题根因
- `forward()` 中直接调用 `_cpu_decode_forward()`（带 `@torch.compiler.disable()`），导致 `torch._dynamo.exc.Unsupported: Skip inlining`
- `forward()` 中调用 `torch.cuda.is_current_stream_capturing()`（返回 bool），在 `fullgraph=True` 模式下不被允许
- `output.copy_(output_cpu.to(query.device))` 在 dummy run 期间触发 `InductorError: LoweringException: AssertionError`

#### 解决方案
将 CPU decode 路径**完全移出 `forward()` 的可编译区域**，放到已存在的 custom op `unified_attention_with_output` 内部执行：

| 修改项 | 说明 |
|--------|------|
| `forward()` 简化 | 移除 `is_pure_decode` 分支，恢复为统一调用 `unified_attention_with_output`；仅保留 `num_prefill_tokens > 0` 时的 async D2H 触发 |
| `unified_attention_with_output` 内嵌 CPU 路径 | 在 custom op 内部判断 `num_prefill_tokens == 0 && not is_cudagraph_capturing() && cpu_kv_cache is not None`，满足条件则走 CPU decode 路径（D2H 同步 → KV 搬运 → CPU Attention → 结果搬回 GPU） |
| `_cpu_paged_attention_fallback` 注册为 custom op | 使用 `direct_register_custom_op(..., dispatch_key="CPU")` 注册，避免 CPU tensor 输入时 dispatch 失败 |
| 移除 `@torch.compiler.disable()` | `_cpu_decode_forward()` 不再被 `forward()` 调用，装饰器自然失效 |

### 2. 修复 CPU Attention Fallback 数值 Bug

| Bug | 修复方式 |
|-----|---------|
| `RuntimeError: tensor size mismatch at dim 0` (44 vs 32) | `torch.matmul(q_seq, k_seq.transpose(1,2))` 的 batch 维度不匹配（`num_query_tokens` vs `num_heads`）。改为 `torch.einsum('qhd,hkd->qhk', q_seq, k_seq)` 和 `torch.einsum('qhk,hkd->qhd', scores, v_seq)` |

## 关键设计决策（本迭代更新）

1. **Custom Op 作为 CPU 路径的"避风港"**：`unified_attention_with_output` 本身就是 custom op（torch.compile 不可见），将 CPU 路径内嵌其中，既避免了 graph break，又无需新增 op 接口。

基于最新复测结果，新增三层结构拆解记录：

|---|---:|---:|
